# Requirements — TravelCraft

> ระบบแนะนำสถานที่ท่องเที่ยวแบบ Gamified Interactive Map
> วันที่: 06/09/2026 | เวอร์ชัน: 0.1 | สถานะ: Draft (ยืนยันกับที่ปรึกษา)

---

## 1. ภาพรวม (Project Overview)

เดิมผู้ใช้ต้องเปิดหลายเว็บไซต์เพื่อค้นหาสถานที่ท่องเที่ยว: แผนที่เปิด Google Maps, ดูวิดีโอเปิด
YouTube, รีวิวเปิด Google, รูปภาพเปิด Instagram — เสียเวลาและขาดความน่าสนใจ

**TravelCraft** รวมทุกอย่างไว้ในหน้าเดียวผ่าน **แผนที่แบบ Interactive (Gamified Map)** ที่คลิก
ไอคอนเพื่อดูรายละเอียด รูปภาพ วิดีโอ รีวิว และเส้นทาง พร้อมเพิ่มความเป็นเกม (สร้างแผนที่เอง,
เก็บสถานที่โปรด, Level) เพื่อให้การค้นหาสถานที่สนุกและน่าใช้งาน

## 2. Stakeholder

| ประเภท | บทบาท | ความต้องการหลัก |
|---|---|---|
| User | นักท่องเที่ยว, นักศึกษา, บุคคลทั่วไป | ค้นหาง่าย, ข้อมูลครบ รูป/วิดีโอ/รีวิว/เส้นทาง, สนุก |
| Admin | ทีมงาน/เจ้าของเว็บ | จัดการ Base Map/สมาชิก/รีวิว/รายงาน |
| ที่ปรึกษา | อาจารย์ที่ปรึกษา | ขอบเขตชัด, วัดผลได้, ส่งงานทันกำหนด |

## 3. User Persona & User Story

> โครงสร้าง: `ในฐานะ ... ฉันอยาก ... เพื่อ ...` (เชื่อมโยง FR)

- **US-01** ในฐานะ **นักท่องเที่ยว** ฉันอยาก **คลิกไอคอนบนแผนที่แล้วเห็นข้อมูลครบ**
  เพื่อ **ไม่ต้องเปิดหลายเว็บ** → FR-003, FR-005
- **US-03** ในฐานะ **Admin** ฉันอยาก **จัดการ Base Map/รีวิว/รายงาน/สมาชิกเอง**
  เพื่อ **อัปเดตเนื้อหาได้โดยไม่ต้องพึ่งนักพัฒนา** → FR-011, FR-012, FR-013, FR-014, FR-015
- **US-04** ในฐานะ **ผู้ใช้ที่ชอบแชร์** ฉันอยาก **สร้างแผนที่ทริปเองแล้วเผยแพร่ให้คนอื่นใช้**
  เพื่อ **แบ่งปันเส้นทางและสถานที่เด็ดของฉัน** → FR-008, FR-009
- **US-05** ในฐานะ **ผู้ใช้ที่วางแผนเที่ยว** ฉันอยาก **บันทึกสถานที่โปรด** เพื่อ **เก็บไว้ดูและแชร์ทีหลัง** → FR-006

## 4. Functional Requirements (FR)

### 4.1 ผู้ใช้งานทั่วไป (User)

| ID | เรื่อง | คำอธิบาย | เกณฑ์การยอมรับ (Acceptance Criteria) | Priority | แหล่งที่มา | สถานะ |
|---|---|---|---|---|---|---|
| FR-001 | สมัคร/เข้าสู่ระบบ | สมัครด้วยอีเมล+รหัสผ่าน, ล็อกอิน, ออกจากระบบ | ล็อกอินแล้วเห็น profile ของตัวเอง, session จำได้เมื่อ reload หน้า | Must | ข้อ 4.1 | ✅ โค้ดมี (Supabase Auth) |
| FR-002 | กู้รหัสผ่าน | ส่งลิงก์รีเซ็ตรหัสผ่านทางอีเมล | ได้อีเมลและเปลี่ยนรหัสผ่านได้จริง | Should | ข้อ 4.1 | 🔶 มี UI แต่เป็น mock (ยังไม่เรียก `resetPasswordForEmail`) |
| FR-003 | สำรวจแผนที่ Interactive | แสดงแผนที่พร้อมไอคอน POI, คลิกแล้วเห็น popup รายละเอียดย่อ | คลิกไอคอน → เห็นชื่อ/ภาพ/หมวด และปุ่มเข้าสู่หน้าหลัก | Must | US-01 | ✅ โค้ดมี (mock data) |
| FR-004 | ค้นหา/กรองตามหมวด | กรองสถานที่ตามหมวดที่ใช้จริงในแอป: temples (วัด/ศาลเจ้า), cafes (ร้าน/คาเฟ่), viewpoints (จุดชมวิว) | กรองแล้วเหลือเฉพาะหมวดนั้น, รีเซ็ตได้, ไม่ reload หน้า | Must | ข้อ 4.1 | ✅ โค้ดมี |
| FR-005 | ดูรายละเอียดสถานที่ | ประวัติ/ข้อมูล, รูปภาพ, วิดีโอแนะนำ (YouTube Embed), เวลาเปิด–ปิด, ค่าเข้าชม, เส้นทาง | ข้อมูลครบทุกช่อง, มาจาก DB จริง | Must | US-01, ข้อ 4.1 | 🔶 มี UI (data mock; YouTube Embed ทำงานจริง แต่ seed pin ยังไม่มี `videoUrl`) |
| FR-006 | บันทึกสถานที่โปรด (Favorite) | เพิ่ม/ลบสถานที่โปรด | เก็บได้หลายอัน, หลังล็อกอินเข้าถึงได้จากหน้า My Maps, sync กับ DB | Must | US-05 | ✅ ลง DB แล้ว (ตาราง `favorites`, guest เก็บ localStorage, merge ตอน login) |
| FR-007 | รีวิวและให้คะแนน | ใส่คะแนนดาว + ข้อความรีวิว, แก้ไข/ลบรีวิวของตัวเอง | รีวิวปรากฏทันที, คะแนนรวมอัปเดต, เก็บใน DB | Must | ข้อ 4.1 | 🚧 รีวิวลง DB ได้จริง แต่ "คะแนนรวม/ค่าเฉลี่ย" ยังไม่ถูกคำนวณ |
| FR-008 | สร้างแผนที่ของตัวเอง (Map Editor) | เลือก background, วางไอคอน POI, ปรับตำแหน่ง/ขนาด, บันทึกฉบับร่าง | บันทึกแล้วกลับมาแก้ต่อได้ | Could | US-04 | ✅ โค้ดมี |
| FR-009 | เผยแพร่แผนที่สู่ Community | ตั้งชื่อ/รายละเอียด แล้ว publish ให้คนอื่นเห็น | ปรากฏในหน้ากลุ่มเมื่อ publish, ถอดออกได้, มีเจ้าของกำกับ | Could | US-04 | ✅ โค้ดมี (เขียน DB `maps`, owner ถอดออกได้) |
| FR-010 | จัดการโปรไฟล์ | เปลี่ยน avatar/ชื่อผู้ใช้, ดูแผนที่ที่ตัวเองสร้าง | บันทึกได้, ดูรายการ map ของตัวเองได้ | Should | ข้อ 4.1 | ✅ โค้ดมี |

## 10. รายการที่ต้องยืนยัน (Open Questions)

- **Q2:** รีวิวต้องล็อกอินก่อนหรือไม่? (แนะนำ: ต้องล็อกอิน เพื่อป้องกันสแปม — ตรงกับ RLS)
- **Q3:** ผู้ใช้ทั่วไปสามารถแปะ URL วิดีโอ/เพิ่ม POI เองได้ไหม หรือต้อง Admin อนุมัติก่อน
- **Q4:** ฐานข้อมูลควรเริ่มด้วยสถานที่ในประเทศไทย หรือตัวอย่างต่างประเทศ (Kyoto/Paris) ตาม seed เดิม?
- **Q5:** ต้องการระบบ Dark/Light theme เป็นฟีเจอร์ที่วัดผลในรายงานหรือไม่ (มีโค้ดแล้วใน `AppContext`)
- **Q6:** ภาพรวม (ข้อ 1) กล่าวถึง "Level" แต่ไม่มี FR กำกับ — ควรตัดออกจากขอบเขต หรือเพิ่ม FR พร้อมเกณฑ์วัดผล?

## 11. คำนิยามคำศัพท์ (Glossary)

| คำศัพท์ | ความหมาย |
|---|---|
| POI | Point of Interest — จุดสนใจ/สถานที่ท่องเที่ยวบนแผนที่ |
| Gamified Map | แผนที่ที่เพิ่มกลไกเกม: ไอคอน, เก็บรายการ, สร้างแผนที่, อารมณ์ RPG |
| Base Map | พื้นหลังแผนที่ (ภาพ/ธีม) ที่ใช้เป็นฉาก |
| Community Map | แผนที่ที่ผู้ใช้สร้างและเผยแพร่ให้ผู้อื่นสำรวจ |
| RLS | Row Level Security — กลไกจำกัดสิทธิ์ระดับแถวของ Supabase |
